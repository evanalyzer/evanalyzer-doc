Pipelines define the sequence of image processing commands applied to raw inputs to extract specific objects.
EVAnalyzer supports multiple, independent pipelines within a single project.
Each pipeline can isolate and process a distinct image channel, or target pre-existing parent objects.
Because a pipeline can ingest and refine objects generated by a previous workflow step, users can easily construct complex, multi-channel processing architectures to resolve sophisticated biological queries.

## The steps panel

In **Pipelines** mode (`Ctrl+2`) the **steps panel** on the left shows the project's pipelines on top, in a darker area, and below them the steps of the pipeline shown.

![Pipelines mode: the switcher head with CY5 spots, its steps with their category stripes, Threshold open with its settings, the preview's objects on the image](../../../assets/screenshots/screenshot-pipeline.png)

### The pipelines area

The pipelines area lists the pipelines in the order they run. Its head says **Pipelines** and how many run (**4 of 4 run**); **+** (**New pipeline at the end**) adds one. Each row shows:

- its place in the order,
- its name,
- its image source - **Ch 2** with the channel's color from the [Image panel](/guide/images/#image-panel), or **Memory**, **Shared**, **Module**, **Scratchpad** or **None** (see [Image source](#image-source)),
- how many of its steps are on, of all (**5/6**),
- a crossed eye when it is left out of the run. Rows left out are dimmed.

Click a row to show its steps; click the shown one again to show none. Hovering a row shows its buttons: the number turns into a grip to drag the pipeline to another place, **⋯** (**Pipeline actions**) takes the place of the step count, and the eye leaves it out of the run (**Leave out of the run**) or takes it back in (**Include in the run**). Double-click a row to edit the pipeline; `Alt`+click focuses on it - see [Focus mode](#focus-mode).

Between two rows, above the first and below the last, an insert line appears when you point there - _New pipeline · 3_; a click adds a pipeline at that place.

![Pipelines mode with no pipeline shown: the pipelines area with its rows, "Pick a pipeline to see its steps" below](../../../assets/screenshots/screenshot-pipeline-pick.png)

With no pipeline shown, the steps area says _"Pick a pipeline to see its steps"_ - _"Click a row above. The eye says whether it runs."_ A project without pipelines says _"No pipelines yet"_, an empty pipeline _"This pipeline is empty"_.

### Pipeline switcher

Once a pipeline is shown, the pipelines area folds by default to the **switcher head**: the shown pipeline's place, name and steps, **‹** / **›** for the previous and next pipeline (`Ctrl+Page Up` / `Ctrl+Page Down`), how many pipelines run (**4/4 run**) and **⋯**. **⌄** (**Expand the pipelines**) shows the pipelines area again, **⌃** (**Collapse to the switcher**) in its head folds it; EVAnalyzer remembers which you chose.

Click the pipeline's name in the switcher head to open the pipeline list over the steps: the same rows as in the pipelines area, with a search (**Find a pipeline**) and **New pipeline at the end**. Type to narrow the list down; `↑` / `↓` move, `Enter` shows the pipeline, `Space` leaves it out of the run or takes it back in, `Alt+↑` / `Alt+↓` move it in the order (not while a search is typed), `Esc` closes.

![The pipeline list open below the switcher head: Find a pipeline, the rows with their place, name, source and steps, New pipeline at the end](../../../assets/screenshots/screenshot-pipeline-switcher.png)

### Pipeline actions

The **⋯** of a pipeline (a row's, or the switcher head's for the shown one) has **Edit pipeline …**, **Duplicate**, **Save as module…**, **New pipeline above**, **New pipeline below**, **Move up**, **Move down**, **Move to top**, **Move to bottom**, **Focus on this pipeline** and **Delete pipeline…**.

A new pipeline - from **+**, an insert line or **New pipeline above** / **below** - opens the **New pipeline** dialog first. The pipeline is only made when you click **Add**; **Cancel** or `Esc` makes none.

### Image source

**Edit pipeline …** opens the **Edit pipeline** dialog next to the steps panel (**New pipeline** for a new one). The image source is the image the pipeline's first step works on:

| Source                 | The pipeline starts with                                                                                                                                  |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Channel**            | An image channel - the usual choice. The picker shows each channel's name and color.                                                                      |
| **None**               | No image. The first step loads one with [Load Image Channel](/commands/image-processing/load-image-channel/) - useful when a pipeline reads several channels. |
| **Scratchpad**         | An empty image - for pipelines that only work on objects.                                                                                                 |
| **Shared memory slot** | The image an earlier pipeline stored with [Image Cache](/commands/image-processing/image-cache/) in a **Shared** slot.                                       |

![Pipeline name and Image source, next to the steps panel](../../../assets/screenshots/screenshot-add-pipeline-dialog.png)

## Steps

Steps run top to bottom. Each step is one line, like a line of code:

- at the far left its **number** - also its [breakpoint](#breakpoints),
- a colored **stripe** for its category (see below),
- its name and a short summary of its settings (**EVA › View › Step values on a second line** puts them below the name).

Click a line to open its settings right there in the panel. Hovering a line shows its buttons at the end: the **eye** (disable / enable), **⤢** ([step settings](#step-settings)), **⋯** and **⌖** ([pin to Tuning](#tuning-panel)). A selected line takes the keys:

| Key | Action |
| --- | --- |
| `Enter` | The step's settings |
| `Ctrl+/` | Disable / enable the step |
| `F9` | Breakpoint |
| `Ctrl+D` | Duplicate |
| `Alt+↑` / `Alt+↓` | Move up / down |
| `Delete` | Remove the step |

The same actions are in the step's **⋯** menu - **Help** (what the step does), **Settings**, **Disable**, **Breakpoint**, **Duplicate**, **Move up** / **Move down**, **Create module** ([modules](/guide/modules/)) and **Remove step**.

![A step's ⋯ menu: Help, Settings, Disable, Breakpoint, Duplicate, Move up and down, Create module, Remove step](../../../assets/screenshots/screenshot-step-menu.png)

### Step categories

The stripe on a step and in the command picker tells what kind of data goes in and comes out:

| | Category | In → out | Examples |
| --- | --- | --- | --- |
| <span class="evx-cat evx-cat-preprocess"></span> | **Preprocess** | image → image | Rolling Ball, Gaussian Blur, edge detection |
| <span class="evx-cat evx-cat-segment"></span> | **Segment** | image → segmentation mask | Threshold, UNet |
| <span class="evx-cat evx-cat-object"></span> | **Instance Seg.** | mask → labelled mask | Connected Components, Watershed |
| <span class="evx-cat evx-cat-extract"></span> | **Extract** | labelled mask → objects | Extract Objects, Fill Object Holes |
| <span class="evx-cat evx-cat-classify"></span> | **Object** | objects → objects | Classify Objects, Object Math, Voronoi, [Colocalize Objects](/commands/object/colocalization/), [Relate Objects](/commands/object/relate-objects/), [Propagation](/commands/object/propagation/) |
| <span class="evx-cat evx-cat-measure"></span> | **Measure** <span class="evx-new">NEW</span> | objects / image → values | [Measure Image Intensity](/commands/measure/image-intensity/), [Measure Image / Object Texture](/commands/measure/measure-texture/), [Exclude Image](/commands/measure/exclude-image/) - see [Measurement steps](#measurement-steps) |
| <span class="evx-cat evx-cat-dataset"></span> | **Dataset** | all images' objects | the trackers, e.g. [Track LAP](/commands/dataset/track-lap/), and [Measure Track Motion](/commands/dataset/measure-track-motion/) - see [Dataset steps](#dataset-steps) |
| <span class="evx-cat evx-cat-utility"></span> | **Utility** <span class="evx-new">NEW</span> | - | [Script](/commands/image-processing/script/), [Save Image](/commands/object/save-image/), [Image Cache](/commands/image-processing/image-cache/) - fit anywhere |
| <span class="evx-cat evx-cat-component"></span> | **Module ◆** | | A [module](/guide/modules/): several steps bundled into one, with its own parameters |

A typical pipeline flow:

1. **Preprocess** commands reduce noise and enhance the signal (Rolling Ball, Gaussian Blur, …).
2. **Segment** commands separate foreground from background (Threshold), **Instance Seg.** commands split it into single objects (Connected Components → Watershed).
3. **Extract Objects** converts the labelled mask into objects of a class.
4. **Classify Objects** applies size/circularity filters and assigns an object class.
5. **Object** commands perform further analysis (Colocalize Objects, Relate Objects, …).
6. **Measure** commands measure the final objects or the image (texture, colocalization coefficients, image quality, …).

A step can only follow the categories that fit before it: Extract after Instance Seg. (or another Extract), Object after Extract or Object, Measure after Extract, Object or Measure, Dataset after any of those or another Dataset step.

**Utility** steps fit anywhere and don't count for the step after them: it looks past them to the step before.

A command can belong to several categories <span class="evx-new">NEW</span> - [Morphological Transform](/commands/morphology/morphological-transform/) is **Preprocess** and **Instance Seg.**. Its place decides which one it runs as: before a segmentation on the image (Preprocess stripe), after one, e.g. a Threshold, on the segmentation mask (Instance Seg. stripe). Its settings show this as a read-only **Works on** line (_Image_ or _Segmentation mask_); move the step to change it. See [Commands in several categories](/commands/overview/#commands-in-several-categories).

When a fixed sequence of steps isn't enough - for example to retry a step with other settings depending on the image - use a [Script](/commands/image-processing/script/) step: a small program that runs the same commands with loops and conditions.

### Adding steps

Click **Add step** below the steps to open the command picker. To put a step at another place, point between two lines, above the first or below the last: an insert line with a **+** appears (_Insert step · 4_) - click it. Its head says where the step goes (_After step 8 of "CY5 spots"_); two tabs list **Commands** and **Modules**. It shows the commands by category - **All**, **Preprocess**, **Segment**, **Instance Seg.**, **Extract**, **Object**, **Measure**, **Dataset**, **Module** - with your **Recents** first and a search (**Search commands…**). It starts on the categories that fit after the step before - after a Classify Objects, **Object**, **Measure** and **Dataset**. The **Utility** commands (Script, Save Image, Image Cache) have no chip: they are always listed, in their own section. A command of several categories is listed once - under its home category if that chip is on, else under its other category, with a hint naming its home: after a Threshold, Morphological Transform is listed under **Instance Seg.** with _also Preprocess_. The pane on the right describes the chosen command, with its settings, authors and what to cite, and under **RAM** how much memory it needs - on the open image's tiles (or, with no image, on 4096 × 4096 tiles, a whole slide's): e.g. _"… 120 MB per analysis thread, 1.2 GB once for the run (the AI network and its weights; one image at a time)"_. A command that works window by window or object by object says that its RAM doesn't grow with the image's size. **Import bioimage.io model…** sets up an [AI model](/ai/bioimageio-import/).

The picker stays open: each step you add goes in after the one you added before, and the footer confirms it (_"✓ Added Threshold as step 3"_). **Done** closes it. You can also add a command from the [command palette](/guide/workspace/#command-palette) (`Ctrl+K`).

![The command picker next to the steps panel: category chips, the list, and the description pane of Colocalize Objects with its RAM and what to cite](../../../assets/screenshots/screenshot-add-pipeline-step.png)

### Step settings

A step's settings open right in the panel (click its line), or in the **step settings** dialog next to the panel (**⤢**, `Enter`, or **Settings** in its ⋯). The dialog - _"Threshold · step 4 · settings"_ - has **General** and **Advanced** as tabs, the step's description, and a search over all its settings.

**Number fields** can be typed into, or changed without typing: drag sideways over the number (one step per 4 pixels), `Ctrl` + mouse wheel, `↑` / `↓`, or the **−** / **+** buttons beside it (not on the small fields).

![Threshold · step 4 · settings next to the steps panel: General and Advanced tabs, the search, the description and the setting rows](../../../assets/screenshots/screenshot-step-settings.png)

### Advanced settings

To keep the steps short, each command shows only its essential settings. Settings that rarely need changing - fine-tuning options of the AI models, filters and object commands - are under **Advanced** (with the number of them). If you changed an advanced setting from its default, it says so (**· 2 changed**), so modified settings are never hidden unnoticed. Tick **Always** to show the advanced settings of every step; EVAnalyzer remembers this. Some dropdowns offer extra choices only in the advanced section - it says where (_"More choices in: Partners"_).

### Problems

Settings that can't work - a class that doesn't exist, a module parameter that no longer matches - are marked **⚠** on the step, with the number of problems. The **Problems** panel lists all of them; click one to go to its step. Some problems come with a fix one click away - **Add class _N_** for a missing class, **Stop setting _<setting>_** for a module parameter that no longer matches, **Store class _N_** for a [dataset step](#dataset-steps) working on an [intermediate class](/guide/classification/#what-goes-into-the-results).

## Tuning panel

When a pipeline is nearly right, the last few settings that matter are often spread over several steps. **Pin** them to keep them together: the pin next to a setting (shown, like its **?**, while you point at the row) adds it to the **Tuning** panel, docked below the image; **⌖** on a step's line pins all its settings (again: unpins them).

The Tuning panel has a tab **All pinned · N**, one tab per step and **Find a setting**. Change a value there and the preview follows - without opening the steps. The pins are saved with the project; **✕** closes the panel, a new pin opens it again.

![The Tuning panel docked below the image: All pinned · 9, a tab for ClassifyObjects, Find a setting, the pinned settings](../../../assets/screenshots/screenshot-tuning.png)

## Live preview

The image shows the result of all steps on the current image. With **Auto preview** on (top bar), any change refreshes it; **Refresh preview** (`F5`) refreshes it once - after switching images, for example. The bottom bar shows how many objects it found.

The preview only works on the part of the image in view. **Preview the whole image** <span class="evx-new">NEW</span> (top bar, `Shift+F5`) runs it on the whole image - the visible part first - and its note says how many objects the whole image has (_"Whole image: 1 204 objects"_). The note stays until another image is shown; a change of the settings cancels a running whole-image preview, or marks a finished one _"Whole image: outdated - settings changed"_.

While the preview runs, a small pill at the top of the image shows its progress; its **✕** cancels it. An image that takes a moment to open shows _"Opening <name>…"_ in the same pill first (no ✕), and the bottom bar says **Opening** instead of **Ready**. If the preview fails, the pill says why and in which step - _"Preview failed in cellpose › #3 Blur: …"_. A message too long for the pill opens as a card with the whole text, **Show step** (selects the step in the steps panel) and **Copy message** (for a bug report). Neither blocks the image.

### Measurements panel

When a pipeline or module has [measurement steps](#measurement-steps), the **Measurements** panel on the right (`Alt+5`, **EVA › View › Measurements**) lists what the preview measured, by step: each measurement's name, its step and value - an image's own value (_image_), or the median over the objects (_median of 23 objects_). Its head says **visible part**: like the preview, it measures only what is in view. Click a row to show its step. When an [Exclude Image](/commands/measure/exclude-image/) step would leave the image out, a banner says so and why (_"Excluded from the results: …"_).

![The Measurements panel on the right with 15 values: the banner "Excluded from the results: Mean intensity (channel 1) of intensity_01 = 270.7, above 250" on top, then a row per value - its name, its step and "image", and the value](../../../assets/screenshots/screenshot-measurements-panel.png)

### Breakpoints

To see the image as it is after a step - not just the final objects - set a **breakpoint**: click the step's number at the far left of its line (or `F9`). Each click goes one further:

- **Stop** (red) - the preview stops at this step and shows its image.
- **Snapshot** (orange) - the preview keeps the image of this step and runs on to the end.
- **Off**.

The steps panel's footer then offers **Breakpoint image**: which image of the step to show (e.g. **Processed image**). Breakpoints can't be set on the steps inside a module; on a module's own line, it stops after the whole module.

### Compare with the original

With a breakpoint image, **Compare** in the top bar shows the breakpoint image and the original side by side, with a divider between them:

- drag the divider to move the cut; near an edge it snaps there and shows only one side,
- click the divider's handle to swap the sides,
- hold `Space` to see the whole original.

Compare stays on when you move the breakpoint or show another image, frame or Z slice; the split comes back once the preview has run again (right away with **Auto preview** on).

While comparing, the [histogram](/guide/images/#histogram) offers **Original | Breakpoint** - the breakpoint image has its own black and white points.

![A breakpoint on Threshold, Compare on: the breakpoint image left, the original right, the divider between them; the histogram offers Original or Breakpoint](../../../assets/screenshots/screenshot-compare.png)

### Measurement steps

**Measure** steps - category **Measure** in the command picker - add values to the results without changing any object. They come after the objects are final (after the Extract and Object steps), so they measure what ends up in the results. Some measure the **image** - one value per image plane, of the whole image or of the area a class covers (the **Measure Image …** commands, e.g. [Measure Image Quality](/commands/measure/image-quality/), [Measure Image Area Occupied](/commands/measure/area-occupied/)) -, others measure **each object** of a class (the **Measure Object …** commands, e.g. [Measure Object Shape](/commands/measure/measure-object-shape/), [Measure Object Distance To Parent](/commands/measure/measure-distance-to-parent/)). Colocalization and texture come as a pair: [Measure Image / Object Colocalization](/commands/measure/measure-colocalization/) and [Measure Image / Object Texture](/commands/measure/measure-texture/). A value that points to another object - the nearest neighbour, the parent - stores that object too.

Every measurement step has an **ID**, unique in the project, which names its values: a value's key is _ID/measurement_, and the results show it as **ID · measurement** (e.g. **coloc_01 · Pearson**). A new step gets the next free ID of its kind (`coloc_01`, `coloc_02`, …); a duplicated step gets a new one. An ID may only have letters, digits and `_`, and IDs that differ only in case count as the same - both are reported as [problems](#problems) on the step. A module with a measurement step that is used twice measures under the same ID twice: make the ID a [module parameter](/guide/modules/#exposing-settings-as-parameters), so each use gets its own.

Later steps choose measurements by these names - [Exclude Image](/commands/measure/exclude-image/) for example leaves an image out of the results by **Rules** that compare a **Measurement** with a **Value**. The values show in the [Measurements panel](#measurements-panel) while you tune, as columns in [Results](/guide/results/#list-view) and in the [measurements export](/guide/results/#exporting-results).

### Dataset steps

Most steps work on one image (or one tile of it) at a time. **Dataset steps** - category **Dataset** in the command picker - run **once after every image has been analysed**, on the stored objects of all images, frames and wells, without pixels. Tracking objects through a time-lapse is the main example: [Track LAP](/commands/dataset/track-lap/), [Track Kalman](/commands/dataset/track-kalman/), [Track Overlap](/commands/dataset/track-overlap/) or [Track Nearest Neighbor](/commands/dataset/track-nearest-neighbor/) - followed by [Measure Track Motion](/commands/dataset/measure-track-motion/), which measures how each track moved. Dataset steps run in the order of the pipeline, so Measure Track Motion goes after its tracker.

Add dataset steps at the end of a pipeline, after the objects they use are classified. They only work on project classes, and they don't run in the live preview - only in an analysis. A dataset step reads the stored results, so it finds no objects of an [intermediate class](/guide/classification/#what-goes-into-the-results): the step gets a warning, and **Store class _N_** sets the class back to **Objects**.

## Focus Mode

A project with several pipelines quickly fills the viewer with channels and object classes that have nothing to do with the pipeline you are working on. **Focus mode** shows only what belongs to the shown pipeline:

- only the pipeline's **image channel** (all channels if the pipeline reads from a scratchpad or memory source), and
- only the **object classes** the pipeline creates, reads or filters on.

While a pipeline is focused, a banner **Focused on "…"** appears above the channel and class lists, so hidden channels and classes never look like a bug. Click **Show all** in the banner to leave the focus.

| Action | Effect |
| --- | --- |
| **⌖** (**Focus mode**) at the foot of the steps panel | Switches focus mode on or off. While on, showing another pipeline moves the focus to it. EVAnalyzer remembers this setting. |
| **Focus on this pipeline** in a pipeline's **⋯**, `Alt`+click on a pipeline, or `F` | Focuses this pipeline right away (`F` uses the shown one). Doing it again on the focused pipeline shows everything again. |

Focus mode only changes what is displayed. Your own visibility settings for channels and classes are not touched - leaving the focus restores them exactly.

![A pipeline focused: the "Focused on …" banner above the classes, only its channel visible](../../../assets/screenshots/screenshot-pipeline-focus.png)

## Reusing a pipeline

**Save as module…** in a pipeline's ⋯ turns the whole pipeline into a [module](/guide/modules/) and saves it to the library: it then appears in the command picker under **Module** in every project, as one step with the parameters you choose.

## Saving a Project as a Template

You can save an entire project - its class definitions, plate configuration, and all pipelines - as a **project template**.

Click **EVA › Save as template…** to open the template dialog.
Fill in **Name**, **Short description**, **Description**, **Author**, **Organization** and optionally **Category**, **Version** (count it up when you change the template) and **Tags**, then click **Next…** to choose a save location.
Project templates use the `.evatemplate` extension.

To create a new project from a template, use **EVA › New from template…** or **New project from a template…** on the Start page.
This pre-populates the classes, plate settings, and all pipelines, so you can start a new experiment with a known-good configuration without rebuilding from scratch.

You can also open an `.evatemplate` file directly with **EVA › Open…** - EVAnalyzer detects the project-template extension and applies it the same way **New from template…** does, so a template downloaded or shared with you doesn't need a separate import step.

![The Save as template dialog: Name, Short description, Description, Author, Organization](../../../assets/screenshots/screenshot-save-as-template.png)

:::tip
Use project templates to standardize analysis configurations across your lab - share a single `.evatemplate` file to ensure every team member starts from the same pipeline and class setup.
:::

## Running the Analysis

Once all pipelines are configured, click **Run** at the top right. The **Run analysis** dialog opens below it, shows how many pipelines and images will run, and asks for an optional **Job name** - left blank, the generated name shown in the field is used (_Leave blank to use "brave_otter"._).

If the pipelines have dataset steps, the dialog offers **Only run the dataset steps**: no image is analysed again - the dataset steps run on a copy of an earlier analysis (chosen from the list), saved under the new job name. Use it to try other tracking settings without re-analysing every image.

While the analysis runs, **Run** in the top bar turns into its progress (**Analyzing ▬ 12 / 48 · ~2 s**) and **Stop**; the window stays usable (see [Working while an analysis runs](/guide/workspace/#working-while-an-analysis-runs)). When it is done, **Analysis finished · N images** offers **Open results**.

![The top bar while an analysis runs: Analyzing, a progress bar, 12 / 48 images, about 2 s left, Stop](../../../assets/screenshots/screenshot-analysis-running.png)

Results are written to a folder of their own in the project's folder, named by the start time and the job name:

```
<project folder>/results/<date>__<job_name>/<job_name>.evadb
```

Next to the database, `<job_name>.evaproj` keeps a copy of the exact settings the run used - open it to see, or restore, what produced these results.

## Best Practices

- Add **one pipeline per image channel** you want to analyze.
- Add **separate pipelines** for object-processing steps (colocalization, in-cell counting) that operate on already-extracted objects.
- Pin the settings you keep adjusting to the **Tuning** panel instead of opening step after step.
